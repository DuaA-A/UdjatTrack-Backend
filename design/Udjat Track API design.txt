1. Base Configuration
Field
	Value
	Base URL
	http://localhost:8080/api/v1
	Authentication
	Bearer JWT — include in every protected request
	Content-Type
	application/json
	Token Expiry
	Access Token: 15 min   |   Refresh Token: 7 days
	Pagination
	?page=0&size=20&sort=createdAt,desc
	

1.1 Roles
Role
	Description
	SUPER_MANAGER
	Platform owner. Manages fleet manager accounts and subscriptions.
	FLEET_MANAGER
	Manages drivers, vehicles, and trips for their fleet.
	DRIVER
	Operates trips via the mobile app.
	

1.2 Standard Response Envelope
All responses follow this envelope:
{
  "success": true | false,
  "data": { ... } | [ ... ] | null,
  "message": "Optional info or error description",
  "errors": [ "Validation error detail" ]  // present on 400
}


1.3 Standard Error Codes
Code
	Meaning
	TRIP_NOT_FOUND
	No trip matches the given ID.
	DRIVER_NOT_ASSIGNED
	The driver has no active vehicle assignment.
	INVALID_STATE_TRANSITION
	Trip state change is not allowed (e.g. END before START).
	UNAUTHORIZED_ROLE
	The caller's role does not permit this action.
	TELEMETRY_INVALID
	Telemetry payload is missing required fields or out of range.
	VEHICLE_ALREADY_ON_TRIP
	The vehicle is already assigned to an active trip.
	DRIVER_ALREADY_ON_TRIP
	Driver is already assigned to an active trip.
	ACCOUNT_PENDING_APPROVAL
	Fleet manager account awaits Super Manager approval.
	SOS_ALREADY_ACTIVE
	An SOS is already open for this trip.
	RESOURCE_NOT_FOUND
	Generic — entity not found.

4. Trip Management & History (REST)
Fleet Managers create trips. Drivers control the lifecycle (start, break, end). Fleet Managers can remotely terminate.


4.1 Trip State Machine
Transition
	Who triggers it
	PLANNED → ONGOING
	Driver: POST /trips/{id}/start
	ONGOING → Paused
	Driver: POST /trips/{id}/Paused
	Paused  → ONGOING
	Driver: POST /trips/{id}/Resumed
	ONGOING → FINISHED
	Driver: POST /trips/{id}/end
	ONGOING → CANCELLED
	Fleet Manager (remote): POST /trips/{id}/cancel

6. Events
Safety events sent immediately (not on the heartbeat schedule) when a critical condition is detected. Each event may auto-create an Alert and/or Incident.


6.1 Event Types
eventType
	Trigger source
	DROWSINESS
	AI fatigue model — eye closure / yawning / head nod
	HIGH_RISK_FATIGUE
	AI model — combined high-risk threshold breached
	UNCONSCIOUS
	AI model — driver unresponsive classification
	CRASH
	IMU — acceleration magnitude exceeds crash threshold
	ROLLOVER
	IMU — gyroscope detects rollover angle
	OBSTACLE_NEAR
	Ultrasonic — blind-spot or forward proximity warning
	DISTRACTION_PHONE
	AI vision — phone usage detected
	BREAK_EXCEEDED

7. Web Dashboard & Real-Time Monitoring (WebSockets)
Replaces continuous REST polling. The Web Dashboard connects to these channels to receive instant updates pushed by the backend EventBus.
Connection Protocol
* Type: STOMP over WebSockets.
* Handshake: Authenticated via JWT token in the connection header.
Channels (Topics)
* SUBSCRIBE /topic/fleet/{fleetManagerId}/telemetry
   * Payload: Streams the updated TripState JSON object every time a truck syncs a new telemetry heartbeat. Used to smoothly move truck icons on the live map.
* SUBSCRIBE /topic/fleet/{fleetManagerId}/alerts
   * Payload: Pushes an Alert JSON object the exact millisecond the backend AlertProcessor generates it (e.g., when a CRASH or UNCONSCIOUS event is processed). Triggers UI pop-ups and red map indicators.
